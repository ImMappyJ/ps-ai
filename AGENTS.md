# PS-AI Development Guide

### Start here

PS-AI is a Photoshop UXP image generation and editing plugin. The 0.5.0 source includes direct ComfyUI / Qwen-Image 2.1 and Bailian, Gemini / Nano Banana and OpenAI Images adapters. Live platform inference and host acceptance await API keys; implemented adapters are not evidence of account or model availability. Read the [README](docs/README.en.md), [ComfyUI setup](docs/setup/COMFYUI.en.md) and [user guide](docs/usage/USER_GUIDE.en.md). See [Bailian](docs/providers/BAILIAN.en.md), [Gemini](docs/providers/GEMINI.en.md), [OpenAI Images](docs/providers/OPENAI.en.md) and the [backend / persistence contract](docs/development/BACKEND.en.md) before platform or server work. The [compatibility manifest](config/compatibility.json) records backend, node and model pins and the scope of validation; the [settings example](config/settings.example.json) defines portable configuration.

The three workspaces cover local editing, Portrait and text-to-image, with eleven modes (including relight and blend). Removal uses a built-in instruction without a prompt field. Character references, effects and atmosphere assets are in scope; routine portrait retouching is not. References do not guarantee identity preservation, and generated results and transparency need inspection. Finding a model in the backend list does not establish compatibility.

Use public guides and current source as the development entry point. Brand geometry lives in assets/brand; regenerate exports after changes and preserve the open frame, monochrome structure and clear space without stretching or adding glow. Ignored handoff notes, historical plans and native evidence are local records, not prerequisites for a clone or fork. Do not publish those directories wholesale.

### Setup and commands

Install dependencies from [package.json](package.json) and the lockfile. CI pins Node in its workflow; the compatibility manifest records tested toolchain versions. The build uses TypeScript and esbuild. Photoshop provides `photoshop` and `uxp` at runtime; do not assume Node filesystem access, subprocesses or full browser APIs.

Release workflow tests execute real PowerShell guards, so local `npm test` / `npm run package` requires PowerShell 7 (`pwsh` on PATH). GitHub's Windows runner already provides it.

```powershell
npm ci
npm test
npm run typecheck
npm run build
```

The output is `dist/plugin`. Enable Photoshop developer mode, restart and load `dist/plugin/manifest.json` through UXP Developer Tool as described in the README. See [plugin/manifest.json](plugin/manifest.json) for the minimum host version; this is not a claim of testing every supported system.

- `npm run package` runs tests, type checking and builds, then produces CCX, Portable and environment-tool archives plus SHA256 files. `PSAI_RELEASE_DIR` chooses a new, empty dedicated directory; the default remains `release/`.
- `npm run brand:export` / `npm run brand:check` exports brand icons / checks that exports are current.
- `npm run p0` **submits real inference jobs to a running ComfyUI**. Inspect [scripts/p0-live.ts](scripts/p0-live.ts) first and ensure `nvidia-smi` is available for VRAM sampling. It currently defaults to `http://localhost:8188` and uses synthetic fixtures; it does not validate real photographs or Photoshop integration.
- `node scripts/build-p0-script.mjs` builds the native UXP probe `dist/ps-ai-p0.psjs`. Inspect the builder and relevant `src/diagnostics/probes/p0-*.ts` before running it in Photoshop.
- For the 16-bit save node, run `python -m unittest discover -s tests -p test_sdr16.py` with backend Python and NumPy installed. This does not replace real inference or native apply tests.

### Contracts to preserve

**Document safety.** Capture freezes the source document, session, dimensions, profile, mode, depth, history, crop coordinates and grayscale mask. Resolve apply targets by source ID, never by whichever document is active. Reject closed, previous-session or modified sources while preserving candidate export. Keep only the validated exception for replacing the plugin's own candidate layer; do not bypass history checks generally.

Context is not the editable area. The effective mask is `M * (1 - P)`, with selection `M` and protection `P`; preserve feathering and original coordinates. Photoshop can trim transparent pixels or return cache-level coordinates: restore actual bounds. Keep pixel and candidate limits and sequential processing to bound full-size buffers. Selection strips must intersect the frozen selection bounds before calling `getSelection`; Photoshop rejects wholly outside or merely touching requests with `Invalid Source Bounds`. Keep outside mask values zero, read valid all-zero strips inside the bounds, and preserve grayscale feathers and native coordinates; do not swallow intersecting read failures. PS27 API checks on 2026-10-19 passed a 20.02MP sRGB8 JPG's irregular selection through ordinary full-context, background and relight capture with zero mask differences and unchanged source state; a separate gray 1/64/128/255 feather sample was exact. This does not validate installed-panel interactions.

Ordinary scopes within the 45M document limit use `captureGeometry.kind: edit-analysis` when native ROI capture cannot fit its pixel/byte budget. Its native-depth source PNG is a bounded working raster; saved masks and `snapshot.bounds` remain native. Never infer mask dimensions from that PNG. Candidate previews read native gray planes sequentially and release them; apply reloads the original task, validates source history and native alpha, then writes bounded strips with one editable mask and one undo step. Feed the writer an aligned/color-matched model raster before source-alpha baking; background strips reconstruct `min(subject, alpha)` against the frozen native source. Do not upsample a locally reconstructed preview and retain alpha a second time. Old records without this marker keep their existing behavior. Model/PNG decode limits remain separate. PS27 synthetic API checks passed ordinary 24M RGB8, 45M RGB16 and 45M RGB8 background capture/strip apply/protection/single undo/preflight cancellation/selection restoration; sampled original pixels were unchanged. A 23.15MP sRGB8 photo duplicate also passed ordinary capture/apply, full current-source pixel hashing, one undo and cancellation after partial writing with exact full-composite restoration; the original document was preserved. This does not validate installed-panel interaction, new inference or lighting quality.

Capture checks required selection bounds and the scope budget before original-file authorization, then revalidates source/selection inside its modal. Missing selection uses `selection-required` guidance. Relight defaults to current selection; explicit `CaptureOptions.selection: 'document'` means full-canvas editable `M=255` without reading/writing the Photoshop selection. Keep it distinct from full context, blend's environment guard and subject-background reconstruction. Relight sessions freeze this scope locally; changing it requires explicit reread/rebind and retains edited lighting. Reopen shows the actual frozen source and scope. Native duplication can leave a color copy without a selection: freeze the mask from the original, retain its source/selection guard and validate the copy against its own history/selection baseline. PS27 API checks at revision 4f18ca2 passed selection and document scope on a public 512x512 PNG8; raw/effective full-mask SHA256 matched the original native plane exactly, with existing documents unchanged. Installed 291c1d40 follow-up verified 21 runtime file hashes and the 0.5.0 build label, correctly rejected a missing selection, then passed actual file-picker/full-selection capture into a tagged copy and workbench with no size error. This does not establish all installed scope controls.

Keep `executeAsModal` limited to capture/write operations, outside network and inference waits. Apply to a new layer with an editable mask and one undo step; roll back failures with `resumeHistory(..., false)`. Keep the mask safely hidden before writing grayscale data, dispose Imaging API resources in `finally`, and preserve original layers.

**Color, alpha and depth.** Inputs are RGB / Grayscale 8/16-bit with a resolved color space. Preserve a current document ICC, including opening-policy conversions; never reinterpret edited pixels using stale disk metadata. For an untagged RGB image with a bound original file, inspect its actual saved declarations through a request-only UXP file entry, bound to the same full path, dimensions and native depth. Static WebP without ICC uses the format's sRGB default; PNG requires an explicit sRGB chunk without higher-priority custom color metadata. Do not infer color from extensions, RGB depth, gamma alone or another file. Unknown/embedded/custom declarations without a loaded document ICC, untagged documents without a bound original file, CMYK, Lab, Indexed, Multichannel and 32-bit HDR take explicit rejection paths. Verified untagged sRGB gets an unmerged, tagged working duplicate; capture and apply target that copy, preserving the original. Preserve unsaved layers in that duplicate: original-file color semantics are assigned to all its untagged pixels, not proof of every later edit's intended colors. Carry protection coordinates to the copy, close failed/temporary copies, and recheck document state after file selection. PS27 native verification read the real WebP entry, preserved the existing Adobe RGB control, and passed an sRGB working-copy identity round trip (zero pixel difference), single undo and cleanup on a disposable untagged RGB8 duplicate. Bounded PNG capture/recovery evidence is recorded separately; reference import, persistent-access controls and broader host acceptance remain pending. Model images, references and masks use sRGB8 / 8-bit, with gamut and precision loss; do not claim a lossless round trip.

Working-copy profile assignment must commit its own history baseline before capture, so undoing a candidate does not restore an untagged, pathless duplicate. Reject an explicit NONE profile type even if its name still reads sRGB. Only exact session-proven preassignment working copies offer explicit color recovery into a new tagged copy; preserve the old document and redo history, then recapture current pixels, selection and protection. Never transfer old candidate permissions or guess the color of arbitrary pathless/earlier-session documents. PS27 RGB8/16 synthetic API checks passed repeated undo, recovered-copy creation and fresh apply/undo/recapture. Installed 0.5.0 b3548bd4 additionally passed explicit recovery after three native Undo operations reached NONE on a public PNG8 working copy in document scope: a new sRGB copy was captured, the old document, edited key light and two old candidates remained, and no old candidate was selected or newly authorized for apply. Other sources/scopes and broader color-recovery checks remain separate.

Main-panel selection recovery is an explicit session-only restoration of the latest successful capture's raw normalized mask (subjectMask for background/scene, selectionMask otherwise), bound to the same document, geometry, native mode/depth and UI mode. It restores no source pixels or old apply permissions; fresh capture rechecks current pixels, history, ICC and protection. Failed captures retain the range cache but cannot submit stale pixels. Native selection restoration/undo acceptance remains pending. Settings and diagnostic details identify the build; only build-time Node reads Git, and dirty or unidentified sources must not claim a clean revision.

Reuse exact authorized FileEntry handles within a session; optional remembering defaults off and stores only a validated private preference plus at most 32 exact native path/token pairs. Tokens originate from user-selected entries and never enter ordinary settings, history, diagnostics or exports. Re-read bounded real bytes on every use; cached access never proves color. Invalid restored access gets at most one picker fallback. Serialize opt-out/clear behind in-flight writes and prevent old operations from restoring cleared grants. Opt-out retains session access; clear drops it on success. Failed persistent removal must report redacted actionable failure and retain useful session access. Existing current ICC bypasses file access entirely. No broad filesystem permission is added; token/installed-panel behavior still needs native acceptance.

Internal RGBA is straight alpha. When “Preserve source transparency” (`preserveAlpha`) is enabled, preserve source alpha without applying semitransparency twice. Validate the clipping base when this path needs one; for unsafe multilayer cases, ask for a merged copy or manual composition after export. Background/scene modes generate opaque environments: disable source-alpha retention and silhouette alignment, white-matte only the model input, and preserve the actual captured source in history. Restore ordinary edit preferences when leaving these modes. The 8-bit template is `qwen21-local-v2-rgba`; SDR16 uses `qwen21-local-v3-rgba16` and optional `PS_AISavePNG16`. Preserve `Uint16Array` values through composition, export and native apply, with separate 8-bit previews. Quantizing to 8-bit then scaling values is not 16-bit preservation. SDR16 does not mean HDR or native 16-bit model precision.

New background/scene tasks select the subject to keep and capture the full canvas. Version `subject-background-v1` uses min(subject coverage, source alpha) to avoid squaring alpha-derived selections, reconstructs translucent pixels against the generated environment at source size, and pairs the patch with its protection-aware layer mask. Persist subject/protection masks as binary; reject incomplete new records, and keep old candidates on their saved behavior. Check raw output coverage before opaque reconstruction. New background/scene tasks disable context color matching and restore ordinary preferences on exit; loading old candidates preserves their saved color matching, while reusing parameters creates a new task with matching disabled. Blend uses full-canvas visible environment outside the original subject selection, but edits only the subject minus protection; alignment and context color matching are disabled for blend. These new paths have offline coverage, not native/inference acceptance.

Validate PNG dimensions, inflation budget, scanlines, CRC and color tags before decoding. Do not fall back to permissive decoding. The untagged-output exception belongs only to the existing verified 8-bit template.

New effect/atmosphere context assets keep `kind: asset` and save `assetContext: selection-v1`. Require paired current source and effective grayscale guide, no imported references, and an explicit model `assetContexts` declaration before upload. Missing capability rejects; unmarked historical assets keep text-only semantics. Input choice is independent of destination. `CaptureOptions.purpose: selection-asset` retains native source depth and permits transparent editable pixels without weakening the relight visibility guard; model input remains sRGB8. Save raw native selection/protection plus their effective mask. Apply reloads the original UUID's PNG and planes, validates expected dimensions/depth before decode, retains output alpha without source-alpha multiplication/alignment/color matching, and applies the native effective mask once, including bounded edit-analysis strips. Fully opaque output remains exportable but cannot apply. Six PS27 synthetic RGB8/16 API cases passed native planes, alpha/feather/protection, small native and large edit-analysis strip application, one undo and injected failure/partial-write cancellation rollback; this uses in-memory saved-task fixtures, not disk durability or installed asset controls. Separately, installed 291c1d40 passed a small RGB8 controlled transparent asset: actual source/guide previews, two uploads/one POST, masked independent-layer apply/one native Undo, and disk History read/reapply without another upload/POST or duplicate; original source retained. This does not cover installed large/RGB16 assets, restart durability or real upstream quality. Five real pinned ComfyUI samples sent both inputs but retained source content or painted guide boundaries: visual acceptance failed despite transparent pixels. Platform request tests are offline; real output still needs keys and acceptance. Never invent alpha or automatically resubmit.

**Backend and jobs.** Settings use `schemaVersion: 1`. Omitted `backend` preserves ComfyUI; `backend: gateway` uses a platform `gatewayModel` ID. API keys are never plugin settings. Accept HTTP(S) origins with optional ports, without paths, credentials or queries. ComfyUI model mappings are filenames relative to backend model directories. The ComfyUI graph supports Qwen 2.1 GGUF, not arbitrary imported UI workflows. New adapters need node-required-input, connection-type, model and real-output validation.

In ComfyUI graphs, the source is the first image, an enabled guide occupies the next slot and references follow it. `JoinImageWithAlpha` restores alpha from `LoadImage`'s inverted MASK; preserve the direct connection without adding another inversion. Preserve image ordering and crop/scale correspondence. Read outputs from save node `8`; missing optional 16-bit support must fail before upload/submission.

For ComfyUI background/scene and blend, omit the grayscale visual guide: the Qwen node encodes every reference into VAE conditioning. Keep the exact effective mask for Photoshop application; gateways retain their provider/native guide path. Background/scene A/B testing reproduced transparent/black background failure. Use concise positive scene instructions without repeating black/white/cutout prohibitions. A selected-area weighted mean alpha below 0.9 warns and blocks background/scene apply, retaining raw output, history and export; never automatically resubmit. PS27 background acceptance used a real 3F3F3F stage output and a disposable RGB8 Adobe RGB copy: source/outside/protected pixel differences and single-undo difference were zero. New installed panel controls, other scenes, 16-bit background inference and platform output still need separate acceptance. Published v0.4.0 packages do not include this correction.

Blend retains full-canvas environment context and applies only to the native subject selection minus protection, without alignment or context color matching. New ComfyUI tasks send source then optional reference, with an environment-based relighting instruction; restore ordinary guide preferences on mode/backend changes and preserve saved historical tasks. The 2026-10-20 real Qwen comparisons used unchanged models, pixel-verified original inputs and fixed seeds with new validation UUIDs. Guide omission produced clear illustration lighting changes, but the portrait remained weak. Saved-raster masked previews preserved outside pixels; they do not prove native full-size application or identity/style/edge quality. Do not describe this limited comparison as universal blending acceptance or pure lighting extraction.

Installed 0.5.0 d2966347 Portable separately passed a controlled-response Blend flow in PS27 on an owned 64x48 sRGB8 source: guide forced off and ordinary preference restored on exit, full-canvas preview, one source upload/one POST/no duplicate, masked independent-layer application with original/outside/alpha unchanged, and one native Undo restoring exact composite and history baseline. The model exchange was 1152x864. Fixture cleanup and exact settings restoration passed. This does not prove real-output quality, exact feather weights, protection, large images, 16-bit, platforms or CCX installation.

Persist the caller-assigned UUID before POST. Recover lost responses by querying that ID, never by automatic resubmission. Historical jobs use their saved backend URL. Filter progress, results and cancellation by job ID. For ComfyUI, use only atomic `/api/jobs/{id}/cancel`, without a global `/interrupt` fallback. Show real stages or steps, not invented timing. Diagnostic traces record stages and task IDs, not private pixels or prompts; classify backend errors rather than assuming every failure is OOM.

Pending records remain visible through a persistent notice and exact History selection. Idle recovery/cancellation freezes the selected UUID before asynchronous work; active cancellation stays bound to the polled task. Only an explicit two-step action for `unknown` may add plugin-local `tracking: detached`; retain state, saved endpoint and every record field. This does not cancel remote work or stop billing, and a separate new generation may duplicate work. Recovery removes detachment and queries the original ID. Use the centralized blocking predicate; never automatically detach or infer a terminal state from missing status. Fifteen consecutive unknown/failed status reads return control with local state unknown; valid queued/running replies reset that count. Private source names belong in history, never traces. These controls have mock coverage, with native acceptance pending.

History separates the focused UUID for details/actions from checked UUIDs for bulk clearing. Use a left date/type/prompt list and right local candidate preview/details, with All/Unresolved filters and 20-record pages; never restore hidden dropdown/form-value state. Show literal original prompts, honest missing-data labels and existing validated candidate composition; browsing must not mutate Results or query a backend. Select all includes every page in the current filter, paging retains checks, and filtering clears them. Programmatic pending/result selection reveals its page and details; terminal recovery retains its focused ID. Selection/navigation changes invalidate confirmations. Lock history callbacks during asynchronous task/local-history actions while preserving active cancellation ownership. Guard stale preview completion and bound decoding/cache memory. Native layout, narrow-panel scrolling and keyboard acceptance remain pending.

Explicit confirmed local history clearing may remove any selected legacy state while idle, including unresolved tasks. Persist minimal cleanup intent before rewriting history or deleting exact UUID-owned source/output PNG and mask/subject-mask/protection-mask BIN entries. Serialize history and standard task binary writes; cleared-ID tombstones prevent late writes or restart from resurrecting blockers. Keep partial cleanup retryable and visible, protect shared references, and skip/report unproven file ownership. Never follow arbitrary saved paths or recurse through directories. Evict deleted candidates and previews without changing Photoshop documents/layers, exports, settings, credentials, original-file grants or lighting drafts. Local clearing does not cancel remote work, stop billing, delete server records or trigger a new submission.

New lighting-layer extraction uses `summary.method: rgb-guided-v2`: multiscale linear RGB lighting ratios retain broad colored lighting and useful local shading while suppressing fine redraw texture. Multiply/Screen fields may carry RGB amounts; preserve legacy scalar and COLOR fields. Do not restore structure similarity scoring or content-boundary rejection. Keep the original content base, exact scope/protection, opacity, color/depth/budget guards and frozen apply authority. Candidate-local fidelity/detailProtection settings (0–1; defaults 1/0.65) live in `relight.localExtraction`, separate from the submitted scene/fingerprint. Explicit adjustment re-derives saved source/output/masks under the same UUID, persists only after success, and uses the same settings for preview/reload/apply without inference or renewed source authority. Coalesce gestures and reject stale asynchronous completion. Legacy summaries/errors remain compatibility data. Hard shadows/rim details can weaken and broad structural edits can still produce artifacts; dated native checks do not establish new visual acceptance.

### Managed platform selection

See [platform setup](docs/setup/PLATFORMS.en.md). Named choices are ComfyUI, Nano Banana (gemini), GPT Image (openai) and BaiLian (bailian); retain the manual gateway option. Optional platform and connections fields extend schemaVersion 1 without breaking old settings; managed localhost imports migrate to 127.0.0.1. Managed URLs are pinned to IPv4 127.0.0.1 (matching the listener; never resolve localhost for managed traffic), with origins at ports 8191/8192/8193 for bailian/gemini/openai; never send a key to an imported arbitrary URL. Preserve each model and ComfyUI address/depth on switching.

ComfyUI must never start a Node process. On Windows, RelayController copies the bundled relay/ assets into the private plugin data folder and calls UXP shell.openPath with launchProcess permission for .cmd. Host consent and Node 24 on PATH are required. Do not bypass a denied consent or assemble commands from model names, keys or prompts. Other systems use a manual gateway. The relay keeps separate stores under relay/provider, proves its identity by provider-bound nonce HMAC before the client sends any bearer/key, then authenticates all remaining routes with a Node-generated private token, rejects foreign Origin/Host, and never follows redirects. API keys are encrypted in UXP secureStorage, sent only after provider identity checks, and kept in server memory. A persisted keyed credential fingerprint blocks different or cleared keys for pending jobs across restart; restore their original account. Saved outputs/raw conversion must remain recoverable without an upstream key. Key storage may be lost; exports intentionally omit it.

Switching to ComfyUI leaves an existing relay running for recovery. Explicit stop shuts down all three listeners and drains work; closing Photoshop does not stop the independent process. Keep the legacy internal cosplay workspace ID for old history and display Portrait. Structured relight uses the existing edit pipeline with semantic lighting instructions and local scene metadata, without new provider fields. Preserve old text-only relight history. Old nine-mode screenshots do not validate the new workbench or results.

Relighting keeps source, local illustration and AI output separate. Freeze the source and scene before submitting; editing lights never submits or recaptures. Native 16-bit source data remains separate from sRGB8 model input. Close the UXP dialog before capture/write and reopen with editor state intact: PS27 native probing rejects apply inside the open dialog. Preview and network run outside executeAsModal. Bind result/application by job ID and source snapshot, retain cancellation/recovery semantics, and mark results stale after scene changes. Eight lights is a product limit, not an accuracy guarantee. Output choices are full-result and lighting-layers; the former compensation experiment and its diagnostics have been removed. Synthetic reconstruction alone does not establish pure lighting layers.

Idle explicit workbench opening and rereading capture the active Photoshop document's current visible composite, including generated backgrounds and merged layers, while retaining edited lights. Reading must not change layer opacity, visibility or content; the former exclusion and separate binding controls are retired. A failed capture retains the prior editor/candidates with an explicit stale reason. Internal dialog reopening after generation/application and reopening during a running task retain the frozen job context without implicit capture. Prior candidates keep their exact submitted snapshots and gain no new apply permission. Continuous controls pair native sliders with precise inputs; begin a gesture before mutation, including Photoshop's input/change-before-keydown ordering, and end or cancel it on termination paths. One gesture is one local undo, with no capture, network request or per-input draft write. Earlier PS27 synthetic API checks passed RGB8/16 Shadow/Light extraction/application, source preservation, grayscale protection, one undo and rollback. Historical installed 0.5.0 b3548bd4 with a controlled local response backend passed one submission/two uploads, lighting-group apply/one native Undo, same-UUID History read/apply without another POST, its former recorded-group exclusion/reread, a reference-only negative blocked from apply, intensity 1-to-3.2 with one local Undo back to 1/no POST, and exactly two output choices. This dated partial evidence does not validate the current-composite change, all controls, other lighting channels or real-photo detail fidelity.

Explicit workbench entry from the main panel must stay closed if the fresh capture fails; retain the previous session, lights and candidates without presenting them as the current source. Reread from an already open editor can retain its stale content. Clear source-read diagnostics only after a complete successful binding; successful retries supersede older feedback for the same feature/source while preserving task history. Disabled clicks, no-op reentry, unrelated sources and older completions must not clear current failures.

For exact session-proven color-copy origins, normalize only the nonauthoritative display name when the native profile type is explicitly NONE. Current capture/apply state remains exact and NONE still rejects normal capture. This does not establish an ICC, add history aliases, survive an adapter restart or authorize recovery of arbitrary pathless documents.

### Platform adapters and server rewrites

The public contract is [BACKEND.en.md](docs/development/BACKEND.en.md), not ignored local notes. UXP hosts the plugin; a separate Node.js 24+ process hosts platform adapters. Never import Node filesystem calls or provider SDKs into UXP. Keys may enter the password field and UXP secureStorage, but never ordinary settings, history, diagnostics or exports. Build output is `dist/gateway/ps-ai-gateway.mjs`; the plugin includes the same bundle and fixed launcher under relay/; environment archives include this standalone bundle and matching notices. Only the small pinned @noble/hashes HMAC/SHA256 helper is added to UXP; platform SDKs stay out.

See the [server structure](docs/development/BACKEND.en.md#server-architecture). main.ts composes and starts the service. HTTP handles transport and connection lifecycle, calling application/jobs.ts. Jobs depend on persistence and providers/contract.ts, never concrete provider classes or incoming HTTP. Adapters depend on the contract, shared protocol and validation; shared must not import upper layers. Keep task state out of routes. Shutdown stops incoming work, drains HTTP handlers, then workers and serialized writes, and finally releases the store lock. Add provider implementations under providers and register explicitly in main, without dynamic loading or another layering framework.

- Select one provider with `PSAI_PROVIDER=bailian|gemini|openai`, then `npm run gateway -- --port 8190`. Concurrent providers need separate ports/data directories. Defaults are `~/.ps-ai/bailian`, `~/.ps-ai/gemini` and `~/.ps-ai/openai`. Manual gateway keys come from the service environment. Managed keys come from the panel through authenticated loopback configuration. The reference binds 127.0.0.1 and provides neither multi-account authentication nor public hosting.

Capabilities constrain operations, image counts, depth, pixels and seeds. `seedMax: 0` means no configurable seed; use placeholder 0 without sending a provider seed. Reject unknown parameters. History restoration must not introduce disabled 16-bit output or unsupported asset modes/settings into platform configuration.

Bailian saves its remote ID and resumes polling. Gemini GenerateContent and OpenAI Images return an image inline, running in a local worker without an invented remote ID. Keep unknown outcomes when neither a queryable ID nor raw result exists; never automatically replay a potentially billable creation.
- Persist raw output before validating/publishing PNG. Temporary I/O failures remain retryable rather than becoming invalid-image terminal states; recover saved raw output by the original UUID. Inputs, references and prompts are private stored data. Diagnostics/responses must not expose content, keys, raw provider errors or signed URLs.
- Migrate jobs, inputs and outputs together. A provider/region change cannot route old jobs elsewhere. One process locks each data directory. After an unclean exit, confirm the process is dead before removing a stale lock. Server reconciliation, task-ID attachment, automatic cleanup and long-term stability guarantees are not implemented; local unknown-only stop tracking does not change server jobs.
- Gateways currently output tagged sRGB8 PNG. Bailian requires exact dimensions; Gemini uses explicit 1K square padding and inverse cropping, with effective-resolution limits for narrow selections or large requests. Untagged output needs explicit per-provider `PSAI_BAILIAN_ASSUME_SRGB=1` / `PSAI_GEMINI_ASSUME_SRGB=1` / `PSAI_OPENAI_ASSUME_SRGB=1` policy. Never relax shared client color/CRC/budget/depth checks.

Gemini excludes transparent effects/atmosphere assets, configurable seeds, 4K, conversations and 16-bit output; validate future additions separately.

Published v0.4.0 assets do not contain these platform changes.

OpenAI JSON images contains source/reference; guide becomes a separate native mask with alpha=255-gray and protected padding. Never carry the old guide image slot into OpenAI prompts.
